# 站内定邀第二阶段：审核包与人工发送记录

本文件记录已实现的本地审核包规则及其后续边界。数据来源为操作者在 TikTok Shop 后台看到并核实的信息；当前不假设平台支持导出、搜索 API 或自动发送。

## 审核包

每批最多 50 人。建立审核包时冻结以下快照，避免商品、佣金或样品规则后续改动使旧批次失去依据：

| 数据对象 | 必要字段 | 规则 |
|---|---|---|
| `targeted_invite_batches` | 项目、批次状态、商品列表快照、佣金比例、合作开始/结束时间、样品审批规则、创建/审核人及时间 | 只能由 `draft` → `reviewed`；审核后修改条件须新建批次 |
| `targeted_invite_items` | 批次、达人、指标与排序快照、个性化切入点及来源链接、草稿文本、草稿审核状态、实际发送与回复状态 | 同一批次不能重复达人；缺内容证据不得伪称看过具体作品 |
| `targeted_invite_events` | 达人、批次、事件类型、实际时间、操作者、站内凭据或备注、创建时间 | 追加记录；草稿、审核、实际发送、接受、拒绝、跟进分别是不同事件 |

商品数量、佣金、期限、样品规则和至多 50 人名单在提交审核前显示在同一个页面。审核人逐条确认个性化切入点和条件。审核通过后供操作者核对并在站内人工发送；应用不调用 TikTok Shop 发送接口。

## 状态约束

- `draft_generated` 和 `reviewed` 都不能写成 `sent`。
- 只有操作者在 TikTok Shop 实际完成邀请后，才能填写发送时间、操作者与可核对的站内标识/证据，并生成 `sent` 事件。邀请失败或未提交应分别记录。
- 七天跟进只针对已有实际发送时间、状态仍未接受且没有更晚回复/拒绝的达人。
- 已在近 30 天邀约、黑名单、内容或受众不契合、证据未齐者，不进入待审核的 50 人名单。
- 每次回填状态都保存事件历史；后续平台 API 若获批，用平台返回的邀请 ID 关联事件，不能用草稿 ID 代替。

## 验收样例

1. 批次含 16 件商品、51 人，或缺佣金/期限/样品规则时，不能提交审核。
2. 只生成草稿或只审核通过，达人仍显示“未发送”。
3. 人工回填实际发送后，批次商品与条件仍可按原版本查看。
4. 第七天有真实 `sent` 事件且未被接受的人进入待跟进；没有实际发送记录的人不进入。

官方 API 接入另立阶段，以店铺权限、沙盒验证及平台当前可用接口为前提，不与本审核包的人工工作流混为一谈。
